# ADR 0002. Стек: FastAPI + Next.js, типы генерируются из OpenAPI

**Дата:** 2026-09-07
**Статус:** принято

## Контекст

Хакатон на двоих, 24–72 часа. Время уходит либо в решение кейса, либо в освоение
инструментов — второго мы позволить себе не можем. Нужен стек, который команда знает
наизусть и который поднимается на чужой машине одной командой.

Отдельная боль прошлых хакатонов: фронт пишет типы ответов руками, бэк меняет поле,
всё молча ломается за двадцать минут до защиты.

## Решение

| Слой | Выбор | Почему |
|---|---|---|
| Бэкенд | Python 3.11 + **FastAPI** + **Pydantic v2** | схемы дают бесплатный `/docs`, его же показываем жюри |
| Пакеты Python | **uv** | секунды вместо минут, лок-файл в репозитории |
| Фронтенд | **Next.js 16** App Router + TypeScript | |
| UI | **shadcn/ui** (Base UI) + **Tailwind v4** | компоненты лежат исходниками: агент правит напрямую |
| Пакеты Node | **pnpm** | лок-файл в репозитории |
| Линтеры | **ruff** + **biome** | один инструмент вместо eslint+prettier |
| Запуск | **make** | уже стоит на macOS и Linux |

**Ключевое решение — мост между фронтом и бэком.** FastAPI отдаёт OpenAPI-схему,
из неё генерируются типы TypeScript (`make types` → `frontend/src/api/schema.d.ts`).
Расхождение всплывает красным подчёркиванием в редакторе, а не `undefined is not
a function` на защите. Сгенерированный файл коммитится: без него у второго участника
после клона не типизируется фронт.

Из этого следует жёсткое правило: **все входы и выходы роутов типизированы Pydantic'ом.**
Нетипизированный роут выпадает из схемы и ломает мост.

## Альтернативы

- **Django / Flask** — отказались: нет автоматической OpenAPI-схемы, значит нет моста.
- **Типы фронта руками или через `any`** — отказались: это ровно тот класс ошибок,
  ради которого выбран FastAPI.
- **tRPC / GraphQL** — отказались: tRPC требует общего TS-рантайма (бэк на Python),
  GraphQL избыточен для десятка эндпоинтов.
- **Библиотека компонентов целиком (MUI, HeroUI, Ant)** — отказались: две системы
  токенов подерутся с Tailwind, и вы чините стили вместо фич. Одна библиотека на проект.
- **eslint + prettier** — отказались: biome делает то же за один шаг и одну зависимость.
- **LangChain / LlamaIndex** — отказались: чужая абстракция усложняет отладку ровно
  тогда, когда она нужнее всего. Обёртка над LLM своя, ~50 строк, в `app/ml/`.
- **Отдельная векторная БД (Qdrant, Weaviate)** — отказались заранее в пользу pgvector,
  когда база вообще появится: минус один сервис в compose.
- **Обучение моделей с нуля** — отказались: готовые эмбеддинги, LLM через API,
  CatBoost на табличных задачах.

## Последствия

- Всё, что не типизировано Pydantic'ом, не доезжает до фронта. Это дисциплина,
  за ней надо следить.
- `make types` нужно помнить прогонять после каждой правки схем. Забыли — типы врут.
- Конфликты в `schema.d.ts` при слиянии веток неизбежны. Разрешаются не руками,
  а повторным `make types`.
- Базы данных в стеке пока нет вообще. Когда понадобится — Postgres + pgvector +
  SQLAlchemy 2.0 без Alembic (`create_all`), и это отдельный ADR.
- Docker пока не собран, запуск локальный в двух вкладках. Пока `docker-compose.yml`
  нет, «работает у меня» проверяется только руками на чужой машине.

Развёрнутое обоснование с разбором каждого слоя — в [../archive/STACK.md](../archive/STACK.md).
