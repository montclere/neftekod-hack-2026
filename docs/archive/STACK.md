# Стек хакатонной команды

Документ-решение. Всё выбрано заранее, чтобы на хакатоне не обсуждать.
Правило одно: **ничего нового во время соревнования.** Проверенный стек, который команда
знает наизусть, выигрывает у модного, который падает в 5 утра. Выбор консервативный
намеренно — усилия должны уходить в решение задачи, а не в освоение инструмента.

## Ядро

| Слой | Решение | Почему |
|---|---|---|
| Язык бэка | Python 3.12 | команда пишет на нём |
| Пакеты Python | **uv** | ставит зависимости за секунды, не за минуты |
| Веб-фреймворк | **FastAPI** | схемы Pydantic дают бесплатный `/docs` — его удобно показывать жюри |
| Валидация | **Pydantic v2** | те же модели идут в API, в ML-пайплайн и в типы фронта |
| ORM | **SQLAlchemy 2.0** | без Alembic, схема создаётся через `create_all` |
| База | **PostgreSQL 16 + pgvector** | векторный поиск без отдельной БД — экономит час на RAG-кейсе |
| Фронт | **Next.js 15** (App Router) + TypeScript | |
| UI | **shadcn/ui** + Tailwind | компоненты лежат исходниками в репозитории: агент их правит напрямую, дизайн гнётся под макет |
| Пакеты Node | **pnpm** | |
| Линтеры | **ruff** (Python) + **biome** (TS) | один инструмент вместо eslint+prettier |
| Контейнеры | **Docker Compose** | одна команда поднимает всё |
| Запуск команд | **make** | уже стоит на Linux и macOS, ставить нечего |

Node 22, Python 3.12. Версии проверить при сборке шаблона — они сдвигаются.

## Мост между фронтом и бэком

**Это самое важное решение в документе.** Классический способ потерять три часа на хакатоне —
фронт пишет типы руками, бэк меняет поле, всё молча ломается в момент демо.

FastAPI отдаёт OpenAPI-схему. Из неё генерируются TypeScript-типы:

```bash
npx openapi-typescript http://localhost:8000/openapi.json -o frontend/src/api/schema.d.ts
```

Кладём в `make types` и в watch. Дальше фронт видит несоответствие в редакторе,
а не в браузере на защите. Бэкендер меняет модель Pydantic — фронтендер сразу получает
красное подчёркивание вместо `undefined is not a function` через два часа.

Один вечер настройки в шаблоне, окупается на каждом хакатоне.

## Фронтенд: разделение зон

| Зона | Чем делаем | Логика |
|---|---|---|
| Контролы: инпуты, селекты, модалки, табы, дейтпикеры | **shadcn/ui** | ставим через CLI по одному, код остаётся у нас |
| Готовые секции лендинга | **блоки shadcn** | закрывают скорость, ради которой обычно берут библиотеку целиком |
| Первый экран, ключевой экран продукта | руками на Tailwind по макетам из дизайн-пака | это попадёт в демо-видео и на слайд |
| Автокомплит, командная палитра | **cmdk** | уже под капотом shadcn Command |
| Диапазон дат | **react-day-picker** | база shadcn Calendar |
| Графики | **Recharts** | |
| Сложные таблицы | **TanStack Table** | сортировка, фильтры, виртуализация |
| Формы | **react-hook-form + zod** | |
| Запросы | **TanStack Query** | кеш, ретраи, лоадеры из коробки |
| Локальное состояние | **zustand**, если понадобится | обычно не понадобится |
| Анимация | **motion** | три момента, не больше |
| Карты | **MapLibre** | если кейс географический |

Одна библиотека компонентов на проект. Смешивать shadcn с HeroUI или любой другой
установленной библиотекой нельзя: две системы токенов и темизации подерутся,
и вы будете чинить стили вместо фич.

**Токены задаются до хакатона.** Палитра, радиусы, шкала отступов, пара шрифтов —
в `globals.css`. Главный признак сгенерированного интерфейса это дефолтный серый,
дефолтный синий и дефолтный радиус. Меняете три переменные — продукт выглядит спроектированным.

## Бэкенд: паттерны

- **Стриминг ответов** — `StreamingResponse` + SSE. Текст, появляющийся по слову,
  выглядит на демо в разы живее, чем спиннер на восемь секунд. Дешёвый эффект
- **Фоновые задачи** — `BackgroundTasks`. Celery и ARQ только если реально нужна очередь с ретраями
- **Аутентификации нет.** Пользователь захардкожен. Ни своя реализация, ни готовая
  библиотека — это отдельный кусок работы, который ничего не добавляет к решению кейса
- **Логи** — structlog, только структурные. Никакого APM, трейсинга, метрик Prometheus
- **Загрузка файлов** — прямо в Postgres как bytea или на диск контейнера. S3 не нужен

## ML-слой

- **Ничего не обучаем с нуля.** Фиксируем как правило, а не как компромисс
- **Эмбеддинги** — sentence-transformers локально или через API
- **LLM** — тонкая собственная обёртка на 50 строк. Не LangChain: когда что-то ломается,
  в чужой абстракции вы будете разбираться дольше, чем написали бы сами
- **Табличные задачи** — CatBoost или sklearn
- **Данные** — Polars
- **Замер качества** — скрипт `make eval`, воспроизводимый. Метрика в README должна
  подтверждаться одной командой, иначе на вопрос «как мерили» ответить нечем

## Инфраструктура

```makefile
.PHONY: up down seed types eval lint logs

up:     ## поднять всё
	docker compose up -d --build
down:   ## остановить и снести тома
	docker compose down -v
seed:   ## заполнить демо-данными
	docker compose exec api python -m app.seed
types:  ## сгенерировать TS-типы из OpenAPI
	npx openapi-typescript http://localhost:8000/openapi.json -o frontend/src/api/schema.d.ts
eval:   ## воспроизвести замер метрик
	docker compose exec api python -m app.eval
lint:   ## проверки
	ruff check backend && biome check frontend
logs:   ## логи бэкенда
	docker compose logs -f api
```

Отступы в Makefile — только табы, пробелы дадут `missing separator`.
Если это начнёт мешать, make меняется на `just` один-в-один, ядро от этого не зависит.

**Деплой:** фронт на Vercel, бэк на Railway. Либо всё на VPS через compose + Caddy —
он поднимает HTTPS сам, без возни с сертификатами.

Аккаунты, домен и API-ключи получить **до** хакатона. Задеплоенная ссылка вместо
«сейчас на локалхосте покажем» — это прямые баллы и снятый риск.

**Сиды — не мелочь.** Скрипт генерации реалистичных данных пишется заранее.
Демо на заполненной базе и демо на пустой — это разница между продуктом и заготовкой.

## Инструменты агента

Три независимых слоя, нужны все:

**1. Процесс** — скилы Мэтта Покока, глобально, один раз:

```bash
npx skills@latest add mattpocock/skills/grill-me mattpocock/skills/handoff \
  mattpocock/skills/diagnose mattpocock/skills/git-guardrails-claude-code --global
```

- `grill-me` — прогнать в первые два часа, до написания кода. Стресс-тест замысла
- `handoff` — передача контекста между сессиями, критично на длинной дистанции
- `diagnose` — тяжёлые баги в четыре утра
- `git-guardrails` — блокирует опасные git-команды. Четверо сонных людей в одном репозитории

Полный TDD, `to-spec`, `to-tickets` не берём — это дисциплина для кода, который проживёт дольше недели.

**2. Знание о библиотеках** — в шаблон репозитория:

```bash
npx skills-npm setup     # либо npx @tanstack/intent@latest install
```

Прописывается в `prepare` в package.json. Агент перестаёт галлюцинировать API,
которого в вашей версии Next или TanStack Query нет.

**3. Свой `AGENTS.md`** — конвенции проекта, структура папок, чего не делать.
Пишется один раз, работает на всех хакатонах. По отдаче перевешивает первые два пункта.

## Что не берём

Список такой же важный, как всё выше:

- микросервисы, Kubernetes
- аутентификация в любом виде
- GraphQL
- обучение моделей с нуля
- LangChain, LlamaIndex и прочие тяжёлые обёртки
- отдельная векторная БД при наличии pgvector
- миграции Alembic
- любая технология, которую никто в команде не запускал раньше
- APM, трейсинг, метрики, feature flags

## Сменные блоки под тип кейса

Ядро не меняется. Меняется один слой:

| Кейс | Что добавляем |
|---|---|
| RAG / поиск по документам | pgvector + sentence-transformers + свой ретривер |
| Агенты / tool calling | своя обёртка над LLM + реестр инструментов на Pydantic |
| Табличное предсказание | CatBoost + Polars, фронт превращается в дашборд на Recharts |
| Обработка документов | pdfplumber / python-docx + очередь на BackgroundTasks |
| Геоданные | MapLibre + PostGIS |
